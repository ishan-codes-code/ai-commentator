# Contracts

Interfaces between pipeline stages (vision → observation → match state →
events → commentary → audio) must have explicit schemas.

- Define each stage's input/output shape before implementing the stage.
- Contract changes must be reviewed for compatibility with upstream
  producers and downstream consumers.
- Prefer strict validation at stage boundaries: reject or flag
  non-conforming data with a clear error rather than guessing.

Defined contracts:

- [worker-protocol.md](worker-protocol.md) — the Electron/Python
  interface: how the main process launches `python/worker.py`, the
  NDJSON message types, stage ordering, validation rules, exit codes,
  and what is (and is not) reported as progress.

- [observation-v1.md](observation-v1.md) — one validated vision-model
  observation of a single frame (roadmap milestones 2–3). Includes why
  server-side schema enforcement is unavailable for our model and why
  validation happens in code.
- [adaptive-sampling-v1.md](adaptive-sampling-v1.md) — the LLM-guided
  sequential sampling loop (roadmap milestone M4.1): one wrapper
  response with a validated `observation-v1` half plus a separately
  validated sampling decision, the HIGH/NORMAL/LOW scheduler, the
  fractional observation filename form, the `adaptive_run.json`
  manifest, and cooperative stop semantics.
- [match-state-v1.md](match-state-v1.md) — the rolling match-state snapshot
  rebuilt from validated observations (roadmap milestone 4): fact identity,
  provenance, statuses, update semantics, determinism, and what the
  tracker explicitly does not infer.
- [events-v1.md](events-v1.md) — evidence-grounded gameplay events detected
  offline from stored observations and match state (roadmap milestone 5):
  event identity, candidate-only statuses, the two firing rules with their
  evidence requirements, suppression rules, determinism, and replay
  provenance.
- [commentary-v1.md](commentary-v1.md) — concise commentary lines generated
  offline from validated observations, match state, and event candidates
  (roadmap milestone 7): deterministic templates with evidence-shape
  preconditions, provenance-bound validation, repetition semantics, and
  deliberate silence.
- [script-v1.md](script-v1.md) — the TTS-ready final casting script
  generated by one bounded LLM call over gated claims (roadmap milestone
  8b): natural paraphrase with deterministic grounding checks, explicit
  success/silence/error statuses, chronological segments with derived
  timestamps, and no template fallback.
